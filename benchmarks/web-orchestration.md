# Web orchestration and SVG verification

Issues #327–#333 share this implementation. `npm run web:orchestration:test` runs real Chromium/Firefox/WebKit playback through the source runtime; `npm run package:check` exercises the published facade from an actual local tarball in imperative/Vue/SSR consumers and builds native production bundles. No test browser aliases NativeScript or a framework into Web code.

Coverage includes direct mutable-value keyframes, additive layers, selective replacement, infinite analytic scalar loops, optional progress observation, decay projection/snap, ordered/overlapping sequences, future timeline callbacks, independent child pause, hidden scheduling, callback errors, scope teardown, runtime disposal during a factory, named states and late/replaced references. The SVG cases cover measured/pathLength units, mid-draw reversal, pause/seek, geometry refresh, authored-style restoration, stale owners, cross-context rejection, reduced motion, zero-length geometry, ordinary SVG geometries and shadow-root removal.

Numeric tracks use the existing context clock. Finite DOM and stroke presentation remain WAAPI effects. Progress, subscribed values and bindings request frames only while observed and moving. Boundary timers schedule arrivals and future steps; they do not sample presentation every frame. SVG stroke painting can require main-thread paint; this is not a GPU guarantee. Imperative callbacks require JavaScript at their activation boundary.

Run the interactive examples with `npm run web:orchestration` and `?demo=values`, `decay`, `groups`, `states` or `stroke`. `node benchmarks/web-orchestration/record.mjs` records actual Playwright pointer/keyboard interactions; pass one mode to capture only that scene. Original WebM files, final screenshots and browser/codec/duration metadata remain in the ignored `captures/` directory. Reviewed H.264 output is committed in `docs/public/media/`, with captioned native reference clips in all four translations of `web-orchestration.md`.

The existing English iOS recordings `motion-values-ios`, `controlled-playback-ios`, `motion-controllers-ios` and `shapes-ios` were decoded and visually reviewed again. Native behavior is preserved, including parser defaults. `orchestration-decay-ios` and `orchestration-timeline-ios` reuse the original `decay.mp4` and `timeline.mp4` recordings with only the launch prefix removed (3.0 and 2.5 seconds respectively); there is no speed change, fabricated frame or physical-device claim. The original files remain intact.

Mavis audit: its current Web surface exposes element animate/set, continuous values/followers/bindings and scoped ownership. Direct scalar playback/progress (#218), imperative groups (#219), replaceable named states (#220) and optional decay release (#221) are new adoption issues in `getcortexlabs/mavis-ui`; they explicitly depend on a containing Jolt release. Existing seekable scene issue #194 stays separate. The new SVG need is Lume's application-owned `ConnectionArtwork.vue`, which currently uses a fixed length of 420. Mavis has no declared SVG drawing surface to migrate; no new Mavis renderer/primitive is required for using Jolt directly on that SVG. Lume's Vue choreography helpers remain, and Reveal height remains a Mavis integration with existing Jolt size animation.
