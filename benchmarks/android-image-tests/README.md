# Native image interaction checks

This instrumentation suite drives the optional image lab with real Android input events. It does not call the library's private gesture methods. Run it on a device/emulator reserved for this test: another application taking focus invalidates the input and screenshot results.

Build the package, then the demo with its usual NativeScript Android setup:

```sh
npm run build
cd demo
ns build android --env.production --no-hmr
cd platforms/android
./gradlew :app:assembleAndroidTest -I ../../../../benchmarks/android-image-tests/init.gradle
```

Install both APKs on the same device (replace `SERIAL`):

```sh
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s SERIAL shell am instrument -w org.nativescript.jolt.test/org.rafaelaugusto.jolt.tests.ImageInteractionTest
```

The app and instrumentation must use the same signing key. A release app signed with the local Android debug key can also be tested; this is a local validation artifact, not a distribution build. NativeScript metadata is generated during the build; after changing a Java bridge signature, force a rebuild if incremental metadata still describes the old class.

Read the final `PASS … native image checks` or `FAIL …` result. `am instrument` can exit with shell status zero even when a test reports failure. Pixel comparison failures save `before.png` and `after.png` under the target app's external files directory, printed in the result.

## Coverage

- Programmatic zoom/reset, a two-pointer pinch followed by one-finger pan, and double-tap return to minimum. Native view transforms are sampled to assert no jump when lifting a finger and bounded continuation of the next pan delta. The latter allows Android's input prediction (an injected 30-pixel move was dispatched as up to 45 pixels); pointer-up continuity itself has a one-pixel tolerance.
- Small dismissal, explicit pointer cancellation, vertical dismissal cancellation, and horizontal movement at minimum zoom.
- Accepted dismissal, reopening and repeated disposal/reattachment.
- A real Frame viewer route: zoom, Android system Back, cancellation on the same viewer, and accepted close after normalization.
- Dissolve backend selection and the immediate content update under reduced motion.
- API 33+: identity and stop/restoration pixels in aspectFit, aspectFill, fill and none; repeat with rounded borders and padding.
- API 33+: paused dissolve pixel stability, reversal and native drag distortion.
- API 33+: replacing the source while a renderer owns the image must preserve the replacement.

Identity comparisons permit a small raster-filtering difference (at most 0.5% of sampled pixels may differ by more than 16 channel levels, with a mean maximum-channel difference no greater than 1.5). The additional texture rasterization measured a mean of 0.70 and a maximum of 15 levels in the API 36 emulator's fill case. Pause comparison requires exact equality. These checks catch mapping, clipping and restoration regressions; they are not a full image-quality assessment. Pinch spans deliberately exceed Android's density-scaled minimum physical span before asserting zoom.

Fixtures are generated by `node benchmarks/make-image-fixtures.mjs`: a 384×256 landscape grid and a 256×384 portrait with a transparent corner. No remote image loading is required.

## Validation boundaries

Recorded validation on 2026-10-19:

| Target                                                           | Result                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Physical ASUS Z017DC, Android 8 / API 26                         | 15 native checks passed in the earlier device run, including gestures, Frame navigation/system Back and fallback. The device was disconnected before the final source-wrapper fix; that revision has not been rerun on ASUS. |
| Dedicated API 36 emulator, 1080×2400, 420 dpi, SwiftShader/ANGLE | All 27 native checks passed, including AGSL identity/restoration pixels, source replacement, pause, reverse and distortion.                                                                                                  |
| TypeScript suite                                                 | 653 tests across 35 files passed; the additional destination-wrapper/EXIF regression passed in the 13-test image-effect suite.                                                                                               |
| Build/static validation                                          | Package build, typecheck, benchmark typecheck, formatting, docs build and Android release build passed. iOS release simulator compilation passed; this is not final physical iOS acceptance.                                 |

The final source-wrapper regression keeps the caller's destination reusable after view disposal and preserves Android EXIF rotation on commit. The native fixtures use zero EXIF rotation. The final physical iOS visual/lifecycle pass and controlled performance profiling remain open; these results do not establish every acceptance criterion of #60/#115.

The agreed Android validation matrix is the physical ASUS Z017DC on Android 8 / API 26 plus a dedicated API 36 emulator. The ASUS exercises native gestures and unsupported-GPU fallbacks; the emulator exercises AGSL, including the pixel checks. An additional physical API 33+ phone is not a release gate for this change. Emulator timings cannot establish physical-device frame-rate claims.

The image lab logs `JOLT_IMAGE_EFFECT` records with backend, preparation milliseconds, frame count, longest observed interval and current/peak texture bytes. These counters measure setup and draw scheduling, not GPU execution. The 4,194,304-output-pixel cap is an allocation guard. A controlled cold/warm benchmark with frame-time distributions and concurrent effects on physical Metal and API 33+ hardware is still required before choosing production performance limits.

Additional visual coverage should record iOS gesture/lifecycle and integrated-route results, transformed/scrolled tap origins, and viewport resizing under native input. Shared-element navigation adapters that take over the image transform belong to #24/#117; the included Frame example transitions an ancestor while the photo recipe holds its native pose.
